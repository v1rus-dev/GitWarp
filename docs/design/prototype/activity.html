Commit activity — heatmap (shipped)

A GitHub-style contribution graph: one square per day for the last 52 weeks, colour by number of commits. Both placements ship (activity_strip.rs, welcome_activity.rs) and are drawn below; switch with Placement, and walk the states with State. Hover or focus a day for its count; click a day to act on it.

Shipped: B — a collapsible “Activity” strip above History in the repository window (also drawn on main-1200.html / main-1600.html), and A — the “Your activity” card on the Welcome screen (drawn on welcome.html). Why B is the primary placement:

  • It is where people already are: the Welcome screen only shows with no repository open, and GitWarp reopens the last repository on start.
  • Clicking a day has an obvious, useful result — History filters to that day, in the same window. On Welcome a click has to open a repository first.
  • “Me” is well defined per repository (user.email resolves local → global); across many repositories identities differ.
  • Cost stays to one repository, and the counts can come from history already being loaded. Welcome would run git log in every recent repository on start, including slow or unmounted paths.
  • The strip collapses to a 34px header, so History keeps its rows. It is not in the details dock: the dock belongs to the selected commit, and the 666px grid does not fit a right-hand dock.

A ships as well: a compact “Your activity” card on Welcome, reusing the same component in compact size.

Spec

Grid geometry

  • 53 columns (52 full weeks + the current partial week) × 7 rows; weeks start on the locale’s first weekday (Monday here). Days after today are not drawn.
  • Cell 10px, gap 2px (--sp-1), radius 2px, pitch 12px → grid 634 × 82px.
  • Compact size 8px cell, same gap (pitch 10 → 528px), used when the regular grid + 28px weekday column does not fit. Below that the grid scrolls horizontally, pinned to the newest week.
  • Weekday column 28px: “Mon”, “Wed”, “Fri” on rows 1, 3, 5; --fs-xs, --muted.
  • Month row 14px, 4px above the grid (--sp-2): the month name sits over the column that contains the 1st; it is dropped when less than 3 columns follow the previous label.

All are color-mix(in srgb, token N%, var(--bg)). Neighbouring steps differ by ≥ 1.40:1 in both themes, and the top step clears 4.5:1. Steps 1–2 are under 3:1, so colour is never the only channel: every day has a text label (tooltip and accessible name), the legend lists the ranges, and the total is text. The ramp is accent (blue), not green, to stay with the app’s single accent; the keyboard focus ring sits outside the cell, over the bg, so it stays visible on an accent cell.

Levels (0 + 4 buckets)

  • 0 = no commits. Levels 1–4 are the quartiles of the non-zero days in view (current range + author filter): ≤ q25, ≤ q50, ≤ q75, above.
  • With ≤ 4 distinct non-zero counts, levels are linear: ceil(4 × n / max), so a repository with one commit a day is not drawn as all-hot.
  • Buckets are recomputed when the range or the author filter changes. Hover a legend square to see its range (“3–5 commits a day”).

Header, filter, range

  • Total: “1,234 commits in the last year”, “… commits by you in the last year”, “… in 2025”. Grouped digits, tabular numbers.
  • Author: segmented Me | Everyone, default Me. Me = author email equals the repository’s effective user.email, case-insensitive, after .mailmap. No email → Me is disabled with a tooltip, Everyone is used, and the side text links to Settings → Identity.
  • Range: “Last 12 months” (default) or a calendar year with commits, from a small select. A year uses the same 53-column grid; days outside the year are blank.

Tooltip, click, keyboard

  • Tooltip: “5 commits on Wed, 14 Oct 2026”, “1 commit on …”, “No commits on …”. It appears immediately above the cell, in the kit tooltip style. Unlike the 500 ms cursor tooltip, it must show at once for scanning and anchor to the cell for keyboard focus.
  • Hover: 1px --border-strong ring. Selected day: 2px --text ring with a 1px bg gap. Keyboard focus: 2px --focus ring with a 1px gap.
  • The grid is one Tab stop (role grid, 7 rows × 53 columns). ↑/↓ previous/next day, ←/→ previous/next week, Home/End first/last day, Enter/Space = click, Esc clears the day filter. Focus shows the tooltip; each cell’s accessible name is the tooltip text.
  • Click (B): History is filtered to that day (author filter applied too), with an accent-soft bar “Showing 5 commits on Wed, 14 Oct 2026 · Clear filter Esc” between the strip and the list. The first commit of the day is selected in the dock.

States

  • Loading: every cell is a shimmering --heat-0 skeleton and the total is a skeleton bar. Size and layout do not change.
  • Large repository: counting runs off the UI thread and streams newest-first. Counted weeks fill in from the right, uncounted ones shimmer, and the header shows “Counting… N commits so far”. Levels are recomputed per batch (≤ every 250 ms) and settle when counting ends. Day clicks wait until it ends.
  • Empty repository: all cells at level 0, “No commits yet”. History shows its own empty state.
  • No commits by me: all cells at level 0, “No commits by you in the last year”, plus a link “Show everyone’s commits”.
  • Error: the grid area keeps its height and shows an error icon, “Could not count commits”, git’s message in mono, and Retry.

Data (implementation note)

Counts come from git log --all --since=<range start> --format=%at%x09%aE. That gives the author time and the mailmapped email; each commit is counted once and bucketed by local calendar day of the author date. Where history is already loaded in full, the counts are derived from it instead. Everything runs on a background executor; the UI gets a [u32; 371] per author filter and never blocks. Results are cached per repository and HEAD set, and refreshed after fetch or commit.
